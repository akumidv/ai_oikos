`- <id> · <title> · <status> · <goal ≤12 words>` — status: active | blocked | deferred | done.

## Target

One core checkout serves several installations. An installation is a folder holding the core as
`oikos/` (a relative symlink now, a submodule later):

```
<installation>/
  AGENTS.md        @oikos/OIKOS.md + @.local/AGENTS.md + the organization's rules
  CLAUDE.md        @AGENTS.md
  oikos.yaml       organization, connectors, settings, mcp_servers, brand
  resources/  LANDSCAPE.md
  .local/          git-ignored: AGENTS.md (this machine's paths), catalog.yaml, TASKS.md, working
                   material; closed dot-named stores: .env, .secrets/google/, .browser/
  .claude/ .qwen/ .mcp.json   generated by oikos sync
  oikos -> ../<core checkout>
```

Phase 0 (scrub) is done: OIKOS.md split from AGENTS.md, brand profile (`brand:`),
neutral extension icon and colours, private task ids and paths out of the docs, `auth: sso`.
Phase 1 is in code (docs, `npm test`): the core is no installation any more — the tools
run from an installation or with `OIKOS_HOME`.
